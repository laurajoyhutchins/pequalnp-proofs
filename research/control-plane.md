# Research control plane, first slice

Read-only packet ingestion uses the same public gap feed as upstream advisory.yml, and the upstream guard from the freshly fetched upstream revision. It does not call claim, beat, release or submit. The source and observation time are recorded; the revision and snapshot are adjacent observations, not a transaction with the desk.

Run locally with Node 20+:
    node tools/control/packets.mjs /absolute/upstream /absolute/gaps.json /absolute/new-output 2026-11-23T00:00:00Z

The output contains an index and per-gap packet, exact statement bytes and an explicitly unfinished Lean skeleton. Import closure is the upstream guard's conservative source-level closure, not an elaborated Lean dependency index. Missing or invalid closure is a blocker, not a guessed dependency. The packet includes only documented mathematical context fields. No lease data is requested. The public posted list is not live allocation or authoritative verdict data. An absent status or dependency list remains unknown. Existing source at the target path requires reconciliation.

The GitHub workflow runs on workstation changes, manual dispatch or scheduled activation once workstation becomes the default branch. The read-only ingestion job uploads artifacts; a separate data-only publication job validates the output layout and fast-forwards research/frontier with the packet files. It never executes generated data. Access the latest successful research-packets artifact or the generated Git branch. A missing or stale artifact is not proof of an empty frontier.

## Shared local candidate verification (pilot)

Create a distinct branch named research/candidate-L-<gap suffix> from research/workstation, and commit only the candidate to research/candidates/<gap id>.lean. The push-triggered shared workflow reads the exact commit's candidate bytes without checking out candidate source. It independently fetches the live public statement and current upstream revision, verifies that the upstream authoritative workflow blob matches the reviewed adapter source, and applies upstream guard, closure, build queue, locked compile and original checker. There are no positive/negative controls repeated per candidate. Full checker artifacts are never transferred across trees. The workflow is a fork-local preflight, not the upstream authoritative workflow; it does not claim, release, publish a PR or grant eligibility. Its output is a local receipt. A branch can modify its own workflow, so a local receipt is not an independent attestation of branch trust. Use reviewed workstation workflow and compare source identity before relying on it.

The verification pilot deliberately retains upstream swap, trusted-base build, separate restricted outsider account, network isolation and memory-watch rules. If the upstream sandbox workflow changes, fail closed until the adapter is reviewed. Historical positive regression L-pcx-101 passed full locked checker (run 45288648488); 1,221 constants were kernel rechecked, and its proof/statement SHA-256 match the upstream authoritative run 45287057925. The live candidate path still requires a real live accepted receipt; historical receipts cannot be used for export. Diagnostic caching, submission exporter and authoritative reconciliation remain separate work.

## Submission preparation

A successful live candidate workflow automatically triggers the default-branch preparation workflow (manual dispatch also accepts a run ID). It authenticates the exact run, compares the candidate workflow with the reviewed default-branch version, reads candidate bytes and receipt as data, checks the actual current upstream base, exact posted statement, hashes, verdict and upstream guards. A separate job reconstructs a deterministic Git commit from the current upstream tree with precisely one added plain file, then pushes the immutable submission/<gap>/<candidate-sha>-<base-prefix> branch without force. No PR or lease action is taken. If upstream has advanced from the receipt, or the gap closed/changed, refuse and obtain a fresh full check; this conservative initial policy may cause retries on a busy upstream. Historical receipts cannot be exported. The workflow must pass integration testing before relying on it for external contributions. GitHub Actions workflow_run is privileged; no candidate-controlled code is executed by this workflow. The branch is prepared, not authorized; workers must still confirm live desk eligibility and ownership before submission.

## Verdict reconciliation

The scheduled read-only reconciler searches all upstream PRs authored by the shared account, checks actual GitHub PR state and one-file identity, discovers authoritative runs through upstream collaborator comments, and verifies the run repository, workflow path, dispatch, base branch, exact head, file/blob, statement hash, unquoted verdict line and independently downloaded proof SHA-256. A merge is tracked separately from a checker verdict. Old-head comments, advisory runs, quoted diagnostics, inaccessible logs and contradictory evidence are never promoted to acceptance. A separate write job publishes the generated account-only index at research/verdicts/verdicts.json; historical control #2906 is separate and is not credited to our account. If a fork token cannot access upstream logs the exact-head log verdict remains unknown. Separately, the official public contributor and lemma records can confirm checked credit: match the actual merged PR URL, contributor, exact proof file SHA-256, formal statement SHA-256 and original checker run URL. This fallback was tested on L-pcx-101; no account credit was created by that test. No external writes occur.
