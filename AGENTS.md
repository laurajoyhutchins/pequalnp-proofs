# Research workstation (fork only)
Read upstream README and CONTRIBUTING.md and use the live desk instructions for any claim or submission. This branch is not an upstream submission base. All workers are task-agnostic generalists. Select from the entire current frontier by swarm need, dependency leverage, tractability, available evidence and marginal contribution, not a preferred topic, historical assignment or claim count. Prior checkpoints are optional reusable evidence. Follow actual official allocation and ownership, avoid known duplication, and reassess at every cycle; pivot when a task is settled, superseded or no longer promising. Do not claim if the desk, ownership, or verification is unavailable. Do not confuse those restrictions with a prohibition on mathematical investigation.

Each research session must actually attempt a concrete falsifiable objective: a proof, bounded exact counterexample search, structural obstruction, or other reproducible mathematical test. Target 65% mathematical investigation, 25% computational/formal verification, 5% context retrieval, and 5% coordination/reporting (guidance, not measured quotas). If live services or the checker are unavailable, stop repeated administrative retries; work provisionally from the exact recorded statement and source revision, without claiming or submitting. Avoid known duplicate work. If verification is unavailable, use rigorous derivation and safe exact experiments; report verification limits explicitly. Preserve the attempted objective, evidence, outcome, and smallest remaining mathematical obstacle. No invented results or incomplete upstream submissions.
  
1. Start with the generated research/frontier branch, index.json and packets/<gap-id>/packet.json. These include exact statements, posted context, guard import closure and source identities. Check snapshot freshness and compare against the current official desk and upstream revision; the generated snapshot is not ownership, official priority or authoritative acceptance. If absent, stale or inconsistent, attempt to read upstream strategy and public gap snapshot directly. If unavailable, use a documented exact research checkpoint provisionally, not as evidence of current eligibility or priority. Record the source revision and exact statement. Use tools/research/frontier.py on an explicitly normalized snapshot (see research/README.md); unknown edges remain unknown. Use the source index for candidate theorem names, then verify against Lean.
2. Read related research checkpoints and accepted upstream proof files before duplicating work. Share mathematical subgoals, failed arguments and exact witnesses. Work in distinct branches from research/workstation, not in a common mutable working tree.
3. Use Python for exact experiments and Lean for universal proof. Research files are not automatically eligible as external contributions.
4. Use tools/research/check-candidate.sh in a clean, dedicated checkout of the exact upstream commit, not this research branch. Run only in a disposable isolated environment without credentials; even Lean compilation can execute code. The script uses the upstream guard and checker. Its local verdict is not the authoritative one.
5. Submit only one new permitted file from an upstream-derived branch after reconciling live gap/lease state; no infrastructure, research notes or unsolicited PRs. Release only your own lease with the documented reason. No lease IDs, tokens, or private research context in public Git.
6. Preserve exact evidence and negative results. Coordinate live ownership privately, using an optimistic SHA-checked update, and do not renew idle or another worker's lease. Scheduled runs are not a heartbeat service.

7. For proof iteration, prefer the guarded wrapper with `--diagnostic` or the target-only diagnostic workflow on `research/diagnostic-<task>` with explicit `research/diagnostic-targets.txt`. Read the actual compiler errors and reuse the same isolated checkout when possible. A diagnostic build is not acceptance; run the full original checker on a completed proof before submission. Never put diagnostic infrastructure in the one-file external PR.

8. Warm diagnostics: reuse the isolated checkout or use `PNP_DIAGNOSTIC_CACHE_HOME` outside it for the upstream build queue and diagnostic artifact cache. Hosted `research/diagnostic-*` branches restore exact-pin branch-local artifacts; no full checker may depend on this cache. Group closely related candidate builds in one job when useful, and preserve actual timing receipts. Do not claim that GitHub-hosted jobs are persistent machines.
