## Submission quality ratchet

- Do not export a reduction merely because its conditional theorem builds. Quantify which part of the parent's difficulty disappears; require a checked nontrivial child or a checked argument eliminating a genuine case, and an independent explanation of why the residual task is easier. Equivalent promise changes, renamed hypotheses, routine semantic bridges and bare case splits are research notes, not eligible submissions by themselves. If a proposed reduction fails this test, preserve useful mathematics and work on the remaining obstruction.
- Before exporting a candidate, require an exact-head full local upstream checker receipt, with the posted statement and checker mode (`check`, `refute`, or `reduce`), approved imports, kernel replay, axiom audit, and for reductions all child restrictions. Use `tools/research/check-candidate.sh --kind reduce BASE SNAPSHOT GAP FILE CANDIDATE RECEIPTS` for reductions on a fresh upstream checkout with the current guard. Diagnostics do not qualify. The hosted ordinary-proof candidate exporter is not a reduction exporter; do not mislabel an R_ file as an L_ file to use it.
- Independently re-run finite experiments and assert the semantic classification of counts, not only their totals. Report "compiled", "locally checked", "upstream PR opened", and "authoritatively accepted" as distinct evidence states. Never claim that a run was performed from source alone.
- Verify the cross-fork PR route is authorized before relying on it. A 403 from the upstream PR creation endpoint is a permission failure, not a proof verdict; do not retry through an unapproved credential or proxy. Keep the exact checked source in the fork and hand off an eligible candidate for user-authorized submission if necessary. Do not release as submitted/reduced unless a PR actually exists.
